## 1. Run Goal

## 2. Phase A — Product Experience Audit (`7d04f47`)

Read-only inspection of the real implementation (not docs) across every listed learner/instructor surface, real journey traces through actual route/link targets, and a motion/loading pass. Full detail lives in `docs/CHATGPT_PLAN.md` §3.

**Headline finding:** the learner surface was a fully realized token-based design system; the instructor surface and the two pre-product entry points (login/join) had never adopted it — the instructor Course-manage page alone had ~18 identically-weighted buttons with no hierarchy at all. A P0/P1/P2 debt map (3/7/5 items) and a UX3-1..UX3-7 Slice queue were recorded from this audit.

## 3. UX3-1 — Visual System & Shared Interaction Foundation (`9eefe3d`)

Migrated the instructor Course-manage page, the learner Course page's Topics loading state, and the instructor layout header onto the existing semantic design tokens and shared primitives (`Button`/`ButtonLink`/`Card`/`PageHeader`/`StateBlock`/`LoadingState`), establishing button-hierarchy weights. Added `Skeleton`/`SkeletonRows` and `Input`/`Select`/`Label` primitives, and a global `prefers-reduced-motion` convention. A general-review pass found and fixed three regressions in the mechanical rewrite (a dropped `<main>` landmark; two spots where a `className` tried to override a shared component's own sizing classes — this repo has no class-merge helper, so that pattern is unreliable and recurred twice more later in the Run before being fully internalized).

### Required product-owner checkpoint

Stopped after UX3-1 per the Run brief. Product owner reviewed screenshots and returned: **APPROVED WITH CALIBRATION CORRECTIONS**. The approved direction (calm, mature, professional, restrained, purple/indigo accent, consistent with the learner surface, no gamified redesign) was locked as a durable **Visual Contract** — `docs/UX_SPEC.md` §11 ("UNLOCK Experience Principles & Non-Goals") and §12 (component/desktop-composition implementation principles), covering the whole product (not just learner UX as §1-§10 do). Two concrete calibration decisions were specified: (a) "one dominant primary per screen" applies to instructor surfaces too — Publish is primary, Save is a local secondary action; (b) Course-level and Topic-level destructive actions should read as the same danger family at different stakes (`dangerSecondary` outlined vs `dangerTertiary` text-level). A third finding — mobile reading better than desktop — was named as an explicit ongoing UX-03 requirement, not a one-time fix.

## 4. UX3-1 Calibration Corrections (`01fd917`)

Applied the checkpoint decisions to the reviewed surface: `Button` gained two first-class variants (`dangerSecondary`, `dangerTertiary`, added as real variants rather than `className` overrides, per the pattern above); the instructor Course-manage page's Save/Publish/Archive hierarchy was corrected; the page's container widened on desktop (`lg:max-w-4xl`) with Course-details/Join-settings and Topics/Questions grouped into two-column grids, addressing the desktop-density finding on the one surface reviewed so far. Self-certified LOW risk given direct computed-style assertions proving the exact colors/widths requested — no dedicated reviewer dispatched for this narrow follow-up.

## 5. UX3-2 — Navigation / Information Architecture (`c969e69`)

A focused IA check (grep every route under `src/app/instructor/**`) came first, per the checkpoint's explicit caution against inventing navigation: confirmed there is genuinely no "Students" surface or any other destination beyond `/instructor/courses` and the per-Course manage/topics/questions/import/item-analysis pages — no nav shell was built. Instead: the instructor-dashboard link on the learner `/courses` page is now promoted to a header button for users who actually have an OWNER/INSTRUCTOR membership (computed from data already fetched, no new request), while a pure learner still sees the old low-emphasis footer link; `/instructor/courses` and `/instructor/courses/new` were migrated to tokens/primitives with a 2-column desktop grid. A general-review pass caught a duplicate equal-weight primary CTA on the empty-course state (the page header's "Create Course" button and the empty state's own action rendering simultaneously) — fixed by suppressing the header button when the list is empty.

## 6. UX3-3 — Learner Pre-Product Entry-Point Convergence (`46bb7ee`)

Migrated `login/page.tsx` and `join/[courseId]/page.tsx` — the two screens outside any shared layout, so each needed its own `<main>` landmark — onto the same tokens/primitives. No behavior changed. Today and Progress were checked and correctly left alone: Today as the reference baseline, Progress because it has a single-phase load (no staged reveal), so no skeleton was warranted there per the Plan's own "only where a real layout jump is observed" rule.

## 7. UX3-4 — Instructor Authoring/Import Convergence (`770b374`)

Migrated the question editor, Structured Import preview/confirm page, Item Analysis page, and the root `/` splash. Delegated the mechanical migration to a forked agent carrying the established conventions, then reviewed the diff directly before verifying: found and fixed three instances of the same `grid` missing its mobile-base `grid-cols-1` class (a real overflow risk with a long unbreakable Hebrew string, the same bug already fixed once in UX3-2) before committing. Button hierarchy: Save secondary / Publish primary on the question editor (mirroring the Course-manage precedent); Preview secondary / Confirm primary (recolored from raw emerald to the one brand indigo) on Import; Refresh stays secondary on Item Analysis (a utility action, not a page-level primary). `Card` gained `aria-labelledby`/`aria-label`/`id` pass-through for Item Analysis's two labelled sections; a new `Textarea` primitive was added, justified by three duplicated raw-textarea instances.

## 8. UX3-6 — Evidence-Backed Performance Fix (`b81ff01`)

Measured first, per the Run's own rule: a local mocked-latency Playwright script (300ms per endpoint, request-start timestamps) confirmed a real sequential fetch gate on both the instructor Course-manage page (Topics/Questions waited ~400ms for Course-metadata to resolve first) and the learner Course page (Topics waited ~344ms for context). Neither gate was necessary — both only need the `courseId` already known from the URL, and each authorizes independently server-side (confirmed by reading the actual route/handler code, not assumed). Removed the gates; all fetches on both pages now start within 1-5ms of each other. The learner-page fix trades one harmless, already-authorized wasted request (an OWNER/INSTRUCTOR previewing their own course via the learner-facing page now fires the LEARNER-only Topic-progress endpoint too, but its result is simply never rendered outside the LEARNER branch) for eliminating the waterfall in the majority LEARNER path. A general-review pass confirmed both routes fail closed independently, found no race condition, and caught one stale doc comment (fixed) that still claimed the old "never called for non-learners" behavior.

## 9. UX3-5 — Motion / Feedback (`f5ca16c`)

Added the single highest-priority gap the checkpoint named: immediate pressed-state feedback. Every `Button`/`ButtonLink`, the shared answer-option button (Today and Practice), and the tappable Course/Topic row links now scale down subtly on `:active` (disabled controls give no press feedback). Deliberately did not add a fade-in to the Today/Practice feedback block or any other new transition — that already has focus movement and `scrollIntoView` doing the state-comprehension job, and "no decorative animation for its own sake" (`UX_SPEC.md` §11 item 6) ruled out manufacturing more. Verified structurally (Playwright cannot reliably simulate `:active` via synthetic mouse events in headless Chromium — confirmed separately, not assumed) that the compiled stylesheet defines the expected `:active { scale: ... }` rules and that they inherit the existing reduced-motion convention.

## 10. UX3-7 — Integrated Verification and Run Close (this commit + `e6b91da`)

Building the required before/after calibration matrix surfaced one more real, previously-unaddressed desktop-composition gap: the learner shell's Browse-mode pages (Today, Courses, Progress) were still capped at the old mobile width on every viewport, including wide desktop — the same anti-pattern already fixed on the instructor side. Fixed (`e6b91da`) by splitting the shared `<main>` into a small client component that reads the existing Learn-Mode context: Learn Mode keeps its deliberately constrained width (`UX_SPEC.md` §5 item 24, unchanged), Browse Mode widens modestly (`lg:max-w-3xl`) with the Courses and Progress lists becoming two-column grids on desktop. A general-review pass confirmed the Learn Mode/Browse Mode boundary is exactly the condition gating the real question-answering UI (no risk of the wrong width applying), the existing no-flash guarantee is preserved, and no fixed-width content assumes the old cap.
