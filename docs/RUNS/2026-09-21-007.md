## Handoff Summary

An authorized OWNER or active INSTRUCTOR can now bring an externally
prepared question set (JSON or CSV) into a Course through one canonical,
format-independent import pipeline: paste/upload → Preview (row-by-row
valid/invalid summary, no writes) → Confirm (atomic, all-or-nothing) → real
`DRAFT_ONLY` Questions, publishable through Run 006's existing, unmodified
per-Question publish action. No new schema/migration was required. See
`docs/DEV_STATUS.md`'s "Structured Import V1" section for full current-state
detail — not duplicated here.

## Slices

- **S1** (`bdaae1d`) — canonical `CanonicalQuestionRow` model
  (`src/domain/import/types.ts`) plus JSON/CSV source adapters, one shared
  key-based answer-option contract, `papaparse` added for CSV. Pure
  parsing/mapping, no DB, no auth.
- **S2** (`445a276`) — row-content validation (reusing
  `assertValidQuestionAnswerDefinition`, collecting every row's errors) +
  Topic-name resolution (trimmed/case-insensitive, unique-match-only) +
  `previewImport` (authorize, reject `ARCHIVED`, parse, validate, resolve —
  read-only, no `questions` port at all).
- **S3** (`9109b12`) — `POST /api/courses/:courseId/import/preview`
  (auth-before-DB-construction, DTO-mapped, `MAX_IMPORT_SOURCE_LENGTH`
  HTTP-boundary limit resolving FUB-005) + minimal instructor Preview UI.
  Reviewed by security + general reviewers: NO BLOCKING FINDINGS.
- **S4** (`413c4e4`) — `confirmImport`: a two-phase atomic confirm (Phase 1
  non-transactional reparse/revalidate reusing `previewImport` unchanged;
  Phase 2 opens one `PostgresImportUnitOfWork` transaction, re-checks only
  the mutable invariants a concurrent change could invalidate — actor
  authorization, Course-archived state, each resolved Topic's continued
  Course/active status — then atomically writes via existing unchanged
  `createDraft`/`updateDraft`) + confirm API. Reviewed by DB, security, and
  general reviewers; general reviewer's CORRECTIONS REQUIRED (missing test
  for the Phase-2 membership-revoked TOCTOU path) fixed with an added test
  and a small doc-comment note.
- **S5** (`0e91566`) — Confirm action/success state in the instructor import
  UI, gated on zero invalid preview rows, linking into the existing
  unmodified Course Question list. Reviewed by the general reviewer;
  CORRECTIONS REQUIRED (stale preview/confirm state left on screen after
  editing input; generic error message on a 401/403 confirm response) —
  both fixed.
- **S6** (`0dd4c74`) — one PGlite/real-Postgres integration test proving the
  full JSON/CSV → preview → confirm → `DRAFT_ONLY` → existing-publish
  journey end to end, plus Topic-resolution edge cases and archived-Course
  rejection. Reviewed by the general reviewer; CORRECTIONS REQUIRED (the
  walkthrough's own zero-Questions-created assertions only proved Phase-1
  pre-transaction rejection, never a genuine mid-transaction `ROLLBACK`
  against real Postgres) — fixed by adding a dedicated
  `postgres-import-unit-of-work.test.ts` mirroring Run 006's own
  `postgres-question-unit-of-work.test.ts` commit/rollback pattern, plus a
  doc-comment/test-name correction.
