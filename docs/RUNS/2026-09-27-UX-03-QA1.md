### QA1-B/C/D — Learning feedback, Practice presentation, Progress IA (`814eace`)

**Findings 2/3/4/15 (learning feedback).** A new POST-submit-only `AnswerFeedbackContentRepository` (Postgres impl selects `correct_answer`/`explanation` ON PURPOSE, the exact opposite trust boundary from the pre-answer path) is wired into both the Today and Practice answer routes, returning `correctOptionIds`/`explanation` ONLY in the `ACCEPTED` response — never on any GET/preview path. `QuestionCard` (shared by Today and Practice) now reveals the canonical explanation and marks every option selected-correct / selected-incorrect / missed-correct using the existing `state-solid`/`state-reinforce` design tokens (never `danger` — an incorrect answer is learning feedback, not an error, matching the pre-existing Visual Contract). Answer options are shuffled once per presentation (a `useState` lazy initializer, stable through selection/submit/feedback since the parent already remounts the card per-question via `key`) so position never teaches the correct answer; grading still compares by option id only, never position.

**Findings 5/7 (Practice presentation).** `selectPracticeBatch` now Topic-interleaves Tier 2 (unseen) and Tier 3 (broader coverage) candidates via a new `interleaveByTopic` helper, so a freshly imported course no longer surfaces Questions in raw import/creation order (the reported "Question 1 → 2 → 3 → 4" pattern). Tier 1 — the shared NBA ranking Today also uses — is untouched; a dedicated PGlite integration test (`supabase/tests/postgres/practice-topic-interleave.test.ts`) proves a Tier-1 remediation candidate is never outranked by Tier-2/3 regardless of interleaving, and that raw creation-order clumping is genuinely broken up. Practice batch completion now shows a real correct-count and Topics-touched summary computed from the batch's own data, plus one restrained encouragement line — no score/percentage/gamification.

**Finding 6, 8, 9, PARTIAL grading — explicitly recorded, not implemented.** Same-day Practice repetition/evidence semantics, the Today Daily Plan Budget policy, and a possible PARTIAL grading outcome all require a Learning Engine/product decision this Run has no authority to invent (`.claude/rules/learning-engine.md`). Recorded in `docs/FOLLOW_UP_BACKLOG.md` as **FUB-034** (owned by Run 010 — the exact unresolved decisions are spelled out there, not summarized away). Finding 6 (content-quality/position/length bias signals) recorded as **FUB-035** (owned by Run 011).

**Findings 10/11 (Progress IA).** Progress stays Course-level and scannable: each Course card now shows a real, evidence-only activity summary (`summarizeCourseActivity`: attempted/total coverage, Topics-touched count) instead of the full inline `TopicList`, which was already duplicated on the Course page. No new mastery/percentage claim is computed anywhere.

### QA1-E — Instructor bulk review/publish (`ab03784`)

Finding 1: Structured Import correctly created Questions as Drafts, but the instructor then faced a one-by-one open → inspect → publish → repeat workflow. The fix reuses the EXISTING single-Question `publishQuestion` transaction/endpoint once per selected id — deliberately no new batch persistence model, no new source-of-truth, no new validation path. Selection checkboxes appear only on Questions with a pending draft; "Select all valid" is a selection convenience, not a second validation pass — an individual Question that is not actually publish-ready still fails its own publish call and is honestly counted as a failure, never silently skipped or force-published. Gated off entirely for an ARCHIVED Course.

### QA1-F — Shell/copy (`cea7219`, `0442c91`)

Finding 12: sign-out previously existed ONLY on Today's own `PageHeader` — undiscoverable from Courses/Progress/Course/instructor surfaces. A new shared `LearnerUtilityBar` renders once, above every Browse-mode learner page, in a consistent top-left position (a `justify-between` row's trailing child, already the visual left in this RTL-first app); it hides itself during Learn Mode so it never coexists with Learn Mode's own `יציאה`. The instructor shell got the same top-left sign-out alongside its existing "back to my courses" link. Convention recorded durably in `docs/UX_SPEC.md` §12 item 58.

Finding 13: closed the Hebrew `"היום שלי"` copy audit — 3 non-compliant `-להיום שלי` fused-prefix strings found and fixed (`progress.backToToday`/`goToToday`, `courseView.goToToday`); repo-wide grep confirms zero remaining occurrences of the disallowed patterns.
