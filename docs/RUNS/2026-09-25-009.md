## 4. Important Decisions

- ADR-015 is canonical for learner access: LEARNER + `hasAccess`; archiving only removes a Course from Today. A
  Plan-vs-ADR conflict was found in the S1 pre-commit review and resolved before commit.
- Learner Progress is PUBLISHED-only for V1 — conservative and TEMPORARY. F-04b (Course PUBLISHED→ARCHIVED, incl.
  learner history) remains unresolved.
- S2 entry shape: a global Progress page grouped by the learner's active Courses; archived memberships are
  authorized at the API but not surfaced; no archived-Course navigation path; OWNER/INSTRUCTOR entries from
  `/api/courses/mine` are dropped (the S1 endpoint is learner-only).
- S3 aggregate population deliberately stays non-revoked AND non-archived learners (differs from learner self-read).
- Privacy contract D1: bands `3c>2n` / `n<=3c<=2n` / `3c<n`; both suppression reasons collapse to one
  INSUFFICIENT_DATA; accepted residual: at n=5 one answer can flip a band/eligibility between manual refreshes.
- **Topic ADR (Run-close decision, taken 2026-09-26):** create ADR-018 consolidating flat Topics, soft archive,
  current non-snapshotted `questions.topic_id`, current-derived attribution, and the learner/instructor consumer
  rules. No new behavior; hierarchy and immutable attribution stay deferred (OQ-031).
- **Version-aware SOLID — known limitation, deliberately NOT a backlog item:** an Attempt on an older
  QuestionVersion may keep contributing to the Question-level learning state used by Topic Progress after a new
  version becomes current. Accepted V1 behavior, not a Run 009 blocker; revisit only if later product requirements
  make it actionable.
- **Join-intent root cause:** the login page read `window.location.search` during render. On a client-side
  navigation from `/join/:id` the Next.js App Router renders the destination before updating the browser URL
  (`HistoryUpdater` pushes state at commit), so `next` was lost and sign-in landed on `/today`. Direct loads (typed
  URL, confirmation email) were unaffected, which is why FUB-027 verification passed earlier. Fix: `next` is
  resolved at submit time through the existing `resolveSafeNextPath` allowlist; join remains an explicit user
  action (no auto-join).
